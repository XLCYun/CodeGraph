# 直接提供 Code Graph 接口的语言分析器

关联 [Narrant #205](https://github.com/XLCYun/narrant/issues/205)。本规范包含 2026-10-21 的独立分析器范围、2026-10-22 确认的直接公共协议重构，以及 2026-10-26 确认的 C/C++ 源码审查政策；实现进度另行记录。

## 产品与职责

CodeGraph 是公开、独立的多语言源码分析项目，在同一 `XLCYun/CodeGraph` 仓库维护 `analyzers/`、公共契约、构建打包和固定版本发布。各语言分析器是主要产品，不称为 Native Helper。

每个语言程序自身接收公共 JSON，完成项目 SDK 发现、必要输入检查、源码分析、完整构图与必要图不变量检查，并直接输出公共 Code Graph。移除跨语言 Rust 协议宿主、私有协议转换和分析 worker；同语言可共用模型、协议及适当的实现代码。

调用方负责下载、完整性校验、事务安装、使用租约、按语言调度、多语言合图，以及取消和超时的整棵进程树终止。分析器不下载或安装其他分析器，不存在必经的总 CLI。

Narrant 是首个消费者，继续负责 Git 两侧准备、Code Graph Difference、Review 和界面。只迁图生成；独立项目可用、首个可下载版本和 Narrant 实际接入属于总交付。

## 启动与分发

保留 Rust、TypeScript/JavaScript、Python、Java、Go、C#、C/C++ 七种分析器，支持 macOS ARM64 和 Windows x64。固定公开入口为 `bin/codegraph-<id>[.exe] analyze`；消费者不拼接 Node、Java 或 dotnet 命令。

| 分析器 | 确认的入口形态 |
| --- | --- |
| Rust | 原生 Rust 程序，进程内使用固定 rust-analyzer 库 |
| Python | 原生 Rust 程序，进程内使用固定 Ruff/ty 库；不要求 Python 解释器 |
| Go | 原生 Go 程序 |
| C/C++ | 原生 C++ 程序，保留 Clang 库与必要资源 |
| C# | .NET SDK 生成的 apphost 与随包运行时，进程内执行 C# / Roslyn |
| TS/JS | 薄入口启动随包 Node，由 JS 分析器实现公共协议 |
| Java | 薄入口启动随包 JVM，由 Java 分析器实现公共协议 |

薄入口只定位运行时、设置固定参数与必要运行环境、继承标准句柄和传播退出状态，不解析分析 JSON、不发现目标 SDK、不转换图、不新增分析 worker。macOS 优先用 exec 替换自身；Windows 启动运行时子进程并等待。真实的 Cargo 等工具查询可产生子进程，不要求所有语言恒为一个 PID。

分析器包可包含直接入口及随包依赖，不要求只有一个物理文件。分析器运行时与项目目标 SDK 分开，沿用既有 SDK 发现和只读政策，不自动安装或升级项目工具链，不执行项目构建脚本。Node SEA、jpackage 与其他打包优化不属于本次要求。

## 公共分析接口

每进程一次分析：stdin 接收一个 UTF-8 JSON 对象，调用方写完后关闭 stdin；stdout 输出一个最终 JSON（成功图或可处理的失败说明），随后退出。移除 ready/cancel 消息和常驻会话；完整输入后的 EOF 是输入结束。stderr 用于有界诊断。崩溃、启动失败或强制终止可以没有结果 JSON，消费者检查退出状态与结果是否完整。

输入是一个绝对项目根、可选的项目内相对文件列表和既定分析选项：

- 省略 `files`：按语言选集政策发现源码，形成此次选集。
- `files: []`：返回空图，不扫描项目、不发现目标 SDK。
- 非空文件列表：只为这些文件构图；选集外源码仅用于解析及图外符号，不沿引用扩大完整节点范围。
- 多个独立项目根：调用方分别调用。共同根下工作区、多模块和多配置遵循既有语言政策。

发现遵循各语言的配置与只读加载规则。C/C++ 使用下述源码审查政策；其他语言不以无差别递归扩展名扫描替代项目模型。缺少各语言必需的配置或 SDK、路径逃逸、读取或真实分析失败须明确报错，不能伪装成功空图。保留必要的文件、输入和输出上限。

图保留既定六种类别、稳定身份、自身内容、包含关系、引用、图外符号和扩展字段，以及测试代码选项和 Rust 三档依赖政策。分析器保证必要图不变量；不增加独立复核进程、自动修图或重复验证链。正常 unresolved 引用是合法数据。

线格式、最终响应身份和错误约定见 [公共协议](../protocol.md)；包内依赖见 [包布局](../pack-layout.md)。消费者仍负责安全解码和使用跨进程返回的数据。

## C/C++ 源码审查政策

2026-10-26，用户确认 C/C++ 以源码审查为先。该政策替代公共入口原有的“缺 CDB 或语义诊断即失败”约束，固定 LLVM/Clang 21.1.8 不变，不引入 Tree-sitter，也不运行 CMake 或其他项目脚本。

- 选集决定完整图的源码范围。缺少编译数据库、头文件、类型或构建上下文时仍保留全部选中原文；已确认的结构正常建模，无法确认的声明片段为不透明节点，未知引用为 `unresolved`。
- 每个选中文件有保留完整原文的 `SourceFile` 容器；不透明节点的原文也进入参与比较的规范化 `code`，不能仅依赖展示用的 `source`。
- 宏先限定为 `#` 预处理指令。一般 `#if…#endif` 条件块整体作为一个不透明节点，保留全部分支，不提取块内结构。标准外层头文件保护例外：保护指令分别保存，内部类和函数照常提取。普通宏调用留在所属对象原文，不导出宏展开对象或展开后的关系。
- 省略文件列表时按明确的源码/头文件后缀与依赖、构建缓存和测试排除规则发现；显式列表保持精确选集。空目录或显式空集可返回空图。
- 可用 CDB、明确标准和已批准目标 SDK 只增强可靠引用，不决定覆盖。`arguments` 与 `command` 都仅作为静态数据解释，不执行编译命令，也不扩大读取授权。没有可用上下文时继续源码图；路径、读取、资源上限、期限及内部错误仍有明确失败。
- 严格 CDB、目标标准和原生语义组件夹具继续保留，验证可选语义实现，不充当公共源码覆盖的先决条件。具体成员与提取规则见 [选集政策](../engine-selection.md#c--c-resolution)。

## 验收

- 独立 checkout 可构建、测试、打包和运行，不依赖 Narrant 源码或安装。
- 七个公开入口直接接受同一公共契约；最终响应能核对语言、版本与协议，无私有消息通道或跨语言 Rust 宿主。
- 每语言覆盖配置发现、显式选集、空集、选集外引用；保留语言语义、来源、只读和 SDK 政策的有意义测试。
- 双平台实际验证打包、固定入口、身份、清单、哈希、运行依赖，以及调用方整树取消、管道与退出回收；C# apphost 和薄入口必须实测。
- 源码状态一致由调用方保证；分析器保留所需来源和路径边界，不用成功空图掩盖失败。
- CodeGraph 经人工 PR 审核合并及确切 main 双平台完整 CI 后实际发布首个固定版本；真实可下载字节通过 Narrant 消费验收。
- Narrant 继续两侧图、差异和 Review，相关 PR 合并与收尾后才关闭 #205。旧结构的 CI 不能充当重构证据。

本次不增加 HTTP、公开 Rust SDK、LSP、常驻服务、持久索引、图缓存、新语言、新平台、跨语言 FFI 或公共图差异接口。不发布 Narrant 应用，不增加仓库、Issue 或用户聊天。
